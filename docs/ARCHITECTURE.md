# Scroll Studio 架构

## 数据流

组件库 / 属性面板 / 拖拽 → Pinia 事务 → `PageDocument` → `NodeRenderer`。

0.4 保存将同一 document 写入 IndexedDB 作品记录；预览将同一 document 通过同源 postMessage 发给独立 iframe。iframe 再次做 schema 校验，用相同 `NodeRenderer` 渲染，随后挂载动画。编辑画布始终展示静态设计，预览才运行动画，因此隐藏、位移和拖拽状态互不干扰。

`PageNode` 的稳定 UUID 关联图层、选区、父子关系与动画目标。只有 section 可以包含 children，其他节点是叶节点。正文通过 Vue 插值渲染，不执行导入 HTML。链接和图片地址按协议白名单过滤。

## 状态与历史

- 事务先在副本执行，验证成功后整体替换 document；无变化的操作不会生成历史。
- 历史保留最近 60 个文档快照；撤销后新修改清空 redo 分支。
- 文本连续输入在 750ms 内按节点/字段合并为一条历史，停止输入后重新开始计组。属性即时反映到画布。
- 移动前检查目标是容器，且不位于被移动节点的后代中。列表内向后移动会修正删除带来的索引偏移。
- 编辑器内 JSON 替换仍是可撤销事务；创建新作品生成独立记录，不替换旧作品。进入另一件作品时清空历史、文字输入分组、节点与关键帧选区，避免撤销返回前一件作品。

## 持久化

IndexedDB 数据库 `scroll-studio:projects`（数据库版本 1）包含 `projects` 与 `meta`。`ProjectRecord` 的独立项目 ID 与 `document.id` 分离，保存创建 / 修改时间、revision、结构化 document 与 SVG 布局缩略图。当前文档 schema 仍为 2。

第一次打开作品库时，从旧 localStorage key `scroll-studio:document:v1` 读取文档，经 `parseDocument()` 兼容 v1 / v2 后存入作品库；迁移标记与作品在同一事务提交，多标签页同时初始化也只迁移一次。旧 key 保留为备份，不再用来存放当前作品。迁移失败不会删除旧草稿或写入成功标记；坏草稿显示提示，允许另建作品。

保存为串行 Promise 队列；每次捕获文档快照，IDB 事务校验 revision 后更新记录，已删除记录和过期版本无法写回。只有写入完成且快照仍等于当前文档才清除 dirty；写入期间的新编辑仍保持待保存。修改后 900ms 防抖，路由离开 / 切换前等待保存；失败则留在当前作品。

关闭页面无法等待异步事务，故同步写入 `scroll-studio:pending:<projectId>` 小型恢复日志；再次打开时，revision 匹配则恢复并自动保存，不匹配或损坏则保留日志、暂停自动保存，并提供下载恢复备份。IndexedDB 保存成功后清理日志；日志空间不足不妨碍普通数据库保存，但关闭前写日志失败会触发浏览器离开提示。最近作品 ID 存在 `scroll-studio:active-project:v1`。

损坏草稿的保护使用独立的 `recoveryRequired` 状态，关闭错误提示不会解除保护。普通导入失败不会暂停后续自动保存；只有显式保存或成功导入备份后才解除保护，显式保存失败也会保留原有受保护日志。手机端可从页面菜单保存。

JSON 导入限 2MB、500 个节点、深度 0–12；校验重复 ID、组件类型、枚举、数值区间、颜色与动画参数。导入失败不会替换当前文档。图片采用 URL 引用，不把二进制图片塞进 localStorage。

模板通过 typed factory 创建新树；作品复制重建 document / node / frame ID，同时重映射节点锚点与共享触发目标。缩略图根据实际标题、背景、组件数量与图片占位生成，所有文本转义，经 img data URL 展示；它是布局示意，不是截图。作品库 Pinia 状态只缓存列表，IndexedDB 是持久化来源。

## 预览与响应式

- 设计画布宽度：1120、768、390px；编辑区根据可用空间用 CSS zoom 适配显示。
- 预览 iframe 具有真实独立视口，不以缩小桌面 DOM 假冒手机页面。
- 渲染器使用容器查询：小于 600px 时容器改纵向、标题最大 36px、正文最大 18px、容器内边距最大 24px。
- 暂无每个断点独立的样式覆盖。手机可点击添加、通过按钮排序；精细拖拽以桌面鼠标为主。
- 预览消息同时校验 origin 和 source。关闭预览清理 message 监听，页面重建或卸载清理动画。

## 动画

首页：GSAP 进场 stagger、编辑器示意图视差、区块 reveal、滚动控制的旋转/缩放 timeline、画廊图像视差。原生滚动，不劫持滚轮。

编辑器：每节点保存 enabled、mode、start、duration、trigger、scrub 与 keyframes。关键帧具有稳定 ID、0–1 相对位置、完整 transform / opacity 状态及白名单曲线；首尾位置固定，帧顺序严格递增，数量 2–12。共享时间轴配置保存在文档根部，触发引用必须指向有效节点；删除触发节点或其祖先时，同一事务把触发目标恢复为页面。

`core/motion.ts` 将结构化数据编译成与 DOM 无关的轨道与动画段：段起点 = 轨道起点 + 前帧位置 × 轨道时长，段时长 = 帧位置差 × 轨道时长。`animation/runtime.ts` 将这些段映射到 GSAP fromTo 和绝对时间位置；共享轨道归入一个 timeline，独立模式各自拥有 timeline / ScrollTrigger。编辑器不挂载执行器。

`ScrollTrigger` 使用 clamp 约束触发边界，避免页面底部组件的触发位置不可达。共享 scrub 将滚动距离映射到整条时间轴，秒数表达相对节奏；关闭 scrub 后按秒播放。没有滚动空间时，scrub 显示完成状态，非 scrub 自动播放，以免内容停在透明起始状态。

时间轴试播模式使用暂停的 GSAP timeline；同源 transport 消息控制 seek / play / pause，执行器每 100ms 至多回传一次进度，显式操作与完成状态立即回传。独立触发轨道在此模式保持静态设计。图片 load 只 refresh 触发位置，不再重建时间轴，避免打断播放。渲染 revision 防止旧异步挂载覆盖新页面；iframe 和面板消息都校验 origin / source。

两处动画均使用 GSAP matchMedia，在 `prefers-reduced-motion` 下保持静态设计可见、停止动效，并通过 revert 清理。轨道拖动仅更新临时位置，在 pointerup 时提交一次事务；取消不生成历史，方向键和数值调整也可撤销。关键帧选区及播放进度属于瞬时 UI 状态，不进入文档。当前不含 pin、自定义曲线编辑器或生产发布编译器。

## 时间轴手势 · 0.3

`core/timeline-edit.ts` 负责与 DOM 无关的时间计算，约束开始时间 0–30s、时长 0.1–10s。左端拉伸固定结束时刻，右端拉伸固定开始时刻；关键帧以绝对秒数吸附再转回相对位置，并在相邻帧之间保留有效间隔。密集导入帧使用自适应间隔，百分比键盘编辑保留归一化精度。

`TimelinePanel` 负责缩放、吸附和列表；`TimelineTrack` 绘制单条轨道与帧操作，使用 `useTimelineDrag` 统一处理移动 / 边界拉伸 / 帧拖动。指针捕获、按下时的尺寸和时间快照保证拖出命中范围后仍可完成操作；3px 门槛避免普通点击生成拖动。所有手势在松手时只提交一次，取消和文档替换时释放捕获并丢弃临时数据。

每条轨道的帧按钮与移动 / 拉伸按钮都是独立 DOM 控件，避免嵌套按钮。帧删除拦截冒泡，防止编辑器全局 Delete 快捷键删除整个组件。窗口 / 键盘监听在卸载时移除。界面缩放与吸附设置不需要变更 schema v2。
